# 使用 ECharts Agent 画图

由当前 Agent 理解数据并生成 ChartSpec，服务负责确定性渲染。每次请求产生一张静态 SVG 或 PNG；不需要为了普通画图开启服务端模型。

## 从数据到请求

1. 读取用户指定的数据和用途，确认字段、单位、时间范围与统计口径。CSV/Excel 要先用宿主能力解析成行对象；服务不接受文件上传。数值字符串、空值、重复类别、聚合和排序在本地显式处理，不编造缺失数据，不默默丢行或更改单位。仅在口径缺失会改变结果时询问。
2. 查询当前服务的 `get_chart_capabilities` 或 HTTP 能力接口。按真实返回选择类型、格式与限额；不要假设模型、A2A 或图片托管已启用。
3. 阅读 [ChartSpec 字段映射与语义](references/chart-spec.md)，选择适合数据的类型并组装 `{spec, style, output}`。保留原始数据来源、转换说明和完整请求 JSON，供复核与后续修改。

## 调用方式

- **优先使用已连接 MCP 的 `render_chart`**。通过实际发现的工具名称调用，不硬编码宿主注册名。参数直接是请求对象。已有 ECharts JSON option，或 ChartSpec 无法表达的明确样式需求，可用 `render_echarts`，仍受服务的静态安全子集限制。
- **宿主已有 A2A 能力时**，按 [A2A 任务合同](references/a2a.md) 发现接口、发送结构化任务并保存产物。普通聊天 text part 不能直接当作此服务的输入。
- **只有终端/HTTP 能力时**，按 [传输与保存](references/transports.md) 使用本技能自带的 Node.js 22+ 脚本；无需项目源码或 npm 依赖。`CHART_URL` 必须由用户或既有配置提供，认证从进程环境中的 `SERVICE_API_KEY` 读取，不要把密钥放进对话或命令参数。

只有用户希望把图表规划委托给服务、且发现 `generate_chart` 并确认 `ai.status: ready` 时，才使用服务端生成能力。HTTP/A2A 同样先确认 AI 就绪。说明意图、字段类型、行数及前 5 行有界样例将发送到部署者配置的模型供应商；在既有数据使用授权内调用，不把该路径当作无提示的自动降级。`ready` 仅表示配置完整。普通 `render_chart`/`render_echarts` 不调用服务端模型。

## 保存、检查与修改

- 按返回协议提取真实图片；MCP 元数据或 HTTP 生成接口的 JSON 都不是图片文件。服务不返回下载 URL。保存到用户选择的位置，使用与 MIME 一致的扩展名；不覆盖已有文件，必要时另存版本。
- 确认成功状态、MIME、文件非空和尺寸；具备视觉能力时检查标题、单位、标签遮挡及截断。无法查看时明确说明只完成结构/保存检查。
- 交付图片与可复用请求文件，简述所做聚合、排序或单位换算，以及任何未验证项。原生 MCP/HTTP 生成接口返回的 `spec`、`option` 和 `warnings` 需复核与保留；本技能脚本的 `generate` 命令与 A2A 只交付图片，不导出规划信息。需要精确复核或沿用同一计划时，使用原生 MCP/HTTP，或由当前 Agent 明确编写 ChartSpec。
- “改成横向”“换配色”等修改在上一份请求上进行，默认保留原数据和统计口径，作为新请求渲染并另存；A2A 不支持向旧任务续写。超出 ChartSpec 的样式再考虑受约束的 option，不靠猜测字段反复调用。

## 错误停止规则

检查 MCP `isError`、HTTP 状态和 A2A 任务终态，不能只看网络请求成功。认证、权限、未知地址或数据口径不明确时停止依赖它的调用。确定的字段/格式错误可修正后再调用；429、超时、取消或模型失败不自动重复提交，A2A 有任务 ID 时先查询。每次服务端生成最多已会调用模型两次，客户端不要叠加隐式重试。

可从 [报告柱状图请求](assets/report-bar.json) 复制起步。样例数据是合成数据，不能拿来替代用户数据或呈现为实际统计结果。
