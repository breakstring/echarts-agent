# 接入 ECharts Agent

将用户的 Agent 连接到已部署服务，并用合成数据确认能够获得图表。技能本身不提供网络连接器；使用宿主已有的 MCP、A2A、HTTP 或终端能力。

## 确认目标与凭据

- 优先采用用户提供的服务地址或已有连接配置。`CHART_URL` 必须是服务 origin，例如 `https://charts.example.com`，不含路径、查询参数、片段或 URL 凭据；不要猜测本机端口或把示例域名当作目标。
- 复用宿主已有的安全认证配置。需要新凭据时，让用户在宿主的密钥设置或本地进程环境中配置 `SERVICE_API_KEY`；不要让用户把密钥粘贴到对话、请求 JSON 或命令参数中，也不要读取并打印其值。
- 先检查宿主真正具备的连接与文件保存能力。不要仅因安装了本技能便宣称已经支持远程 MCP 或 A2A。

## 选择连接方式

1. 宿主支持远程 MCP 时，连接 `CHART_URL` 下的 `/mcp`，使用 **Streamable HTTP** 和 Bearer 认证。服务没有 stdio 模式。使用宿主实际发现的工具，不能假设 MCP 注册名称或工具前缀。
2. 宿主已有 A2A 编排能力时，读取受认证保护的 `/.well-known/agent-card.json`，按其接口连接。优先协商 1.0；不要为接入服务擅自升级宿主。
3. 仅有 HTTP 或终端能力时，直接使用 HTTP API。Node.js 22+ 可执行本技能自带的检查脚本，无需安装 npm 依赖：

   ```bash
   node /已安装技能目录/echarts-agent-connect/scripts/check-service.mjs
   ```

   运行前，`CHART_URL` 和需要认证时的 `SERVICE_API_KEY` 应已注入该进程环境。脚本只检查健康与能力，不证明 MCP/A2A 已连接或图片已生成。整次检查默认限时 15 秒；可用环境变量 `CHART_TIMEOUT_MS` 设置 100–120000 的整数毫秒数，不自动重试。

接入、诊断或验证时，阅读 [连接合同与样例](references/connection.md)。

## 验证与交付

- 查询 `get_chart_capabilities` 或 `GET /v1/capabilities`，记录实际支持的类型、格式、限额和 `ai.status`。模型 `disabled` 不妨碍确定性渲染；`ready` 只表示配置完整。
- 通过选定协议发送引用文档中的小型合成数据请求，确认成功状态与图像类型，保存或展示返回图片。不要使用用户业务数据做连通性探测，也不要调用 `generate_chart` 测试连接。
- 只修改本次目标连接所需的宿主设置。不要关闭 TLS 校验、开启匿名访问、修改服务配置或顺带接入其他服务。
- 凭据错误、地址不明、协议不支持时停止相关调用并说明具体缺项；不要循环尝试密钥或静默改换目标。一次超时不能证明请求未执行。
- 交付可复核的结果：连接方式、工具是否发现、能力查询结果、样例图路径/可见产物及未完成项。单独健康检查成功不能表述为“画图已验证”。
